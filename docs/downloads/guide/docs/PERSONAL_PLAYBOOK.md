# 個人のAI秘書として育てる

前提：共通導入を終え、自由な会話とサンプルのナレッジ参照ができること。

## 1. 毎日の場面を1つ選ぶ

朝の予定整理、アイデアの壁打ち、仕事後の振り返りなどから選びます。P02で利用場面・通知・音声を決めます。予定はGoogle連携後、音声入力は認識環境の準備後に使います。

同じ場面で3回使い、実際の行動に役立ったか記録します。機能の数を合格条件にしません。

## 2. 判断基準を記録する

P05で一度に1問答えます。例：「納期が今日、品質が間に合わないとき、お客様へ何と伝える？」。判断、理由、例外、要確認条件を分けます。

templates/判断基準テンプレート.mdを使い、本人の発言とAIの整理を区別します。まだ決めていないことは未決定のままにし、AIの提案を本人の方針として自動登録しません。

## 3. 相談と記録を繰り返す

NORIKOへP06を送り、状況、制約、選択肢を伝えます。根拠が記録にあるか確認し、一般的な提案と区別します。

相談後「今の相談をObsidianに記録して」と依頼し、確認画面のタイトル・本人発言・AI提案を読んで必要なら編集します。「内容を確認して保存」を押して初めて保存されます。表示された保存先のファイルをObsidianで開いて本文も確認します。現状はナレッジ内のAI-NORIKO-Recordsに日付付きの別ファイルを作る方式です。1日1ファイルへの追記など厳密な形式が必要なら、Codexに追加開発を依頼します。

会話AIへ渡すのは直近12メッセージまで、文字数にも上限があります。起動中だけの履歴なので、大切な判断はアプリを終了する前に記録します。話題を変える場合は「新しい相談」で区切ります。

## 4. 過去の素材を取り込む

ChatGPTのエクスポートや本人の講義・録音から最初は3件だけ選びます。利用できる権利のある素材を使い、原本を残してコピーで作業します。P10で本人・相手・AIの発言を区別し、出典・日付を記録します。

文字起こしの金額・固有名詞・判断条件は本人が修正します。成功者の言葉はP09で出典と自分の解釈を分け、長文を丸ごと転載しません。他人の価値観を自分の確定方針に混ぜません。

石橋のりこの考え方を参考にしたい場合は、主催者から受け取る別パックをP21で追加します。[NORIKOナレッジの導入](NORIKO_KNOWLEDGE_SETUP.md)を読み、提供条件・13件の配置・実際の参照を確認します。講師本人の回答サービスではなく、自分の方針とも別です。

## 5. 制作へ引き継ぐ

P11で目的・対象者・完成形・期限を整理し、制作依頼文を確認します。実際にAIを動かすときは対象フォルダ、送る資料、操作を確認します。制作AIの利用枠はNORIKOのローカル会話と別です。

既存プロジェクトの再開は登録済みフォルダを指定します。全作業の統合監視はP13で追加開発します。フォルダ更新だけでAIが完了したとは判断しません。

## 7日間の練習例

| 日 | 内容 | 確認するもの |
| --- | --- | --- |
| 1 | 起動・手動タスク | 自分で再起動できる |
| 2 | 会話AIの準備 | 自由文と追加質問への返答 |
| 3 | 判断基準1件 | Obsidianと参照結果の一致 |
| 4 | 実際の相談 | 根拠・不明点 |
| 5 | 任意連携を1つ | 設定と結果の一致 |
| 6 | 制作依頼文の作成 | 実行前に確認 |
| 7 | 振り返り | 使用回数、役立った場面、改善点 |

企業用へ変える場合は個人の全履歴やGoogleアカウントを社員に渡さず、[企業向け手順](TEAM_PLAYBOOK.md)で専用ナレッジを用意します。
