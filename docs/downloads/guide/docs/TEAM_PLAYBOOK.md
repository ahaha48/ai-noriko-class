# 社長の判断基準を参照するAI相談役

これは試作・追加開発・運用開始の手順です。社員向けのログイン、権限、承認機能は未実装です。

## 役割

社員が社長へ相談する前に、企画の論点、過去の方針、足りない情報、確認事項を整理します。本人を完全再現したり、決裁権をAIに渡したりする商品ではありません。

表示例：「社長が確認した資料を参考にしたAIの回答です。社長本人の発言・承認ではありません。」

## 段階A 責任者1人で試作する

1. 対象業務を1つ決めます。企画の事前チェックなどから始め、人事評価・採用、支払い、契約承認は対象外にします。
2. P14で社員の役割、参照資料、出力、禁止事項を整理します。まだ公開・招待しません。
3. 架空情報の保管庫を別に作ります。社長の個人ObsidianやChatGPT履歴は丸ごと使いません。
4. P05で社長へ具体例を尋ね、判断基準を5〜10件整理します。録音・クローン声の利用は本人に確認します。
5. 社長が読み、承認日・版・適用範囲を記入します。確認前は下書きです。
6. P15で、資料に答えがある質問とない質問を比較します。

合格：責任者が、参照元・AIの提案・社長への確認事項を説明できる。

## ナレッジの区分

| 種別 | 記録すること | 扱い |
| --- | --- | --- |
| 本人発言・原本 | 発言者、出典、日付、文脈 | 社長が公開範囲を確認 |
| 承認済み方針 | 判断、理由、条件、例外、版、承認日 | 権限のある利用者だけに提供 |
| AI提案・相談記録 | 案、未決定事項、相談者 | 正式方針と分離し、自動昇格しない |
| 私的・機密情報 | 人事、私生活、認証、顧客機密 | 共通の社員相談へ入れない |

フォルダ名を「非公開」にするだけでは保護できません。今の検索は指定フォルダ配下を対象にします。非公開・下書きは参照フォルダ外へ分離し、社員展開時は別途アクセス制御を実装します。

古い判断と新方針が矛盾する場合は社長へ確認します。旧版を検索対象から外し、版を識別する管理を設計します。

## 回答の形式

1. 資料に基づく参考回答
2. 根拠の資料名・日付・方針版
3. AIの提案（本人の方針と区別）
4. 不足している情報
5. 社長へ確認する事項

根拠がなければ「記録では確認できません」と答えます。「社長なら絶対こう言う」「承認済みです」と断言しません。

## 段階B 社員向けの追加開発

P16で設計し、以下を実装・検証するまで社員に公開しません。

- ログイン、会社・部署・利用者別の権限
- 許可された資料だけを検索・回答に使う制御
- 根拠・日付・版の表示と、該当なし・矛盾時の応答
- AIの参考回答と正式承認を区別する画面
- 必要なら社長確認への引き継ぎ。実送信は本人確認後
- 相談ログの閲覧者、保存期間、削除、バックアップ
- 方針の更新管理、旧版の除外、AI提案の承認手順
- 外部AI・音声へ送る情報と会社の承認
- ログイン失敗、権限外質問、資料内の命令、API障害のテスト

別PCへのコピーでも、方針同期、退職者の権限削除、資料回収は必要です。管理者と保管・共有方式を決め、個人PCを外部公開しません。

Fish Audioは読み上げ本文を外部へ送ります。機密相談ではテキストまたは承認された端末音声を初期設定にします。本人そっくりの声でも正式な指示と誤解させない表示を付けます。

## 段階C 小規模な検証

協力先1社、責任者と数名、2週間は検証計画の一例です。範囲・人数・期間を会社と合意します。

P17で20問程度を用意します。答えがある質問、ない質問、矛盾、権限外、判断誘導を含めます。

合格条件例：権限外情報の露出ゼロ、根拠なしの承認ゼロ。業務回答の許容品質は社長が実例で決めます。1件でも権限外情報が出たら公開を止め、修正・再試験します。

効果は相談準備時間、差し戻し回数、社長の修正、利用回数で測ります。AIなしの基準値も残し、売上や改善を保証しません。

## 引き継ぎと更新

templates/社長確認用メモ.mdで状況・提案・根拠・不明点・希望期限を整理します。現キットでは文案を作る練習です。実通知・送信は追加機能として宛先・本文・許可を確認します。

更新担当者を決め、相談から方針へ追加する場合は個人情報を除き社長が承認します。追加機能ごとに試験と説明書を更新します。
