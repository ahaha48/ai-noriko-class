# 同じ土台から、自分に合う形へ育てる

最初に [機能一覧](FEATURE_CATALOG.md) で「既存の設定」「使い方の工夫」「追加開発」を区別してください。[共通導入](COURSE_GUIDE.md) が済んだら、[個人秘書](PERSONAL_PLAYBOOK.md) または [社長の判断基準を参照する相談役](TEAM_PLAYBOOK.md) へ進みます。

## 既存の設定で変える

呼び名・AI秘書名・音量・自動読み上げ・朝の報告時刻を、自分の用途に合わせます。Google Calendar／Tasks、Obsidian、Fish Audio、AI実行環境は、それぞれ接続・許可・動作確認が必要です。売上管理は初期非表示の任意機能です。

自由な相談にはAIモデルが必要です。音声をつなぐだけでは相談機能は完成しません。音声なし・テキストから始めても構いません。

## キャラクターを変える

public/assets/ の noriko-character-closed.png（口を閉じた状態）と noriko-character-open.png（話す状態）を、権利のある透過PNGに差し替えます。元の2枚を控え、縦横比を合わせて npm run build で確認します。声も本人または許諾済みのものを使います。

## ナレッジを変える

設定画面の保存先を確認し、その**同じフォルダ**をObsidianで開きます。勝手に別保管庫を作りません。まず公開してよい判断基準1件で保存と検索を試します。原文・要約・AIの推測、出典・日付・承認状態を分けます。templates/ の記入用ファイルを利用できます。

会社用にする場合、個人用ナレッジを丸ごと流用しません。社長に承認された資料だけを対象にします。フォルダ名やプロンプトはアクセス制御ではありません。

## 日本語で追加開発する

[プロンプト集](PROMPTS.md) の P12（追加機能）、P13（統合チェック）、P18（常駐）、P20（用途変更）を、正しいAI NORIKOフォルダを開いたCodexに送ります。同じチャットの継続は便利ですが、正しいフォルダを開くことが重要です。

1. 現状を読んで、追加が必要か確認する。
2. 目的・操作・費用・情報の送り先・対応OS・完成条件を決める。
3. 変更案を確認してから実装を依頼する。
4. 元の動作と新しい動作を試す。
5. 戻し方と説明書も更新する。

資料に例があることは、実装済みという意味ではありません。企業の複数人利用は認証・権限・データ分離・承認・監査等の別開発と検証が必要です。

## 配布する前に

配布物から認証情報、個人ナレッジ、売上、作業結果、node_modules、distを除きます。素材・ソフトウェアの利用条件を確認します。署名済みインストーラー、ログイン時の常駐、企業公開は別の作業です。本キットに講師個人用の常駐アプリ設定は含まれません。
